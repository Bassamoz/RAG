# مراجعة متابعة التشغيل

مراجع مستقل بسياق جديد، قراءة فقط؛ لم ينفذ Docker أو اختبارات ولم يعدل ملفات. اختار المستخدم سابقًا تجاوز الرأي الثاني بنموذج مختلف؛ استُخدمت نتائج المراجعة الحالية فقط.

- ملاحظة P1 صحيحة: وراثة GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE قد توجه أوامر fixture إلى مستودع آخر. اختبار checkout-env-red-20261107 أعاد المسار الخطأ فعلًا. عزل جميع GIT_* عن subprocess والتحقق من حالة root Git HEAD/index أصلح السبب؛ checkout-env-green-20261107 نجح. لا تعديل Git عام أو root commit.
- ملاحظة P2 صحيحة كحد للدليل: snapshot بعد التشغيل الأول لا يثبت حفظ بيانات كانت قبله. صار السكربت يلتقط baseline قبل التشغيل الأول عند وجود .env.dev ويقارن بعدها، ويرفض المتابعة إن تعذر الاتصال بقاعدة موجودة. في bootstrap جديد دون ملف بيئة، يسجل preservation_scope=populated_second_start صراحة؛ لا يزعم إثبات baseline مفقود.
- راجع المراجع الإصلاحين ولم يجد ملاحظات إضافية ملموسة. يبقى إثبات التشغيل الحقيقي مهمة السكربت الجاري والأدلة الفعلية، وليس رأي المراجع.

ظهر لاحقًا فشل pytest بسبب ACL لمجلد Temp مشترك بين حساب sandbox والمضيف. لا تغيير ACL أو تجاهل فحص؛ تحقق checkout يستخدم مجلد pytest جديدًا تحت fixture فريد داخل workspace، ويطبع stdout عند الفشل قبل رفع exit code. الأدلة القديمة محفوظة.
