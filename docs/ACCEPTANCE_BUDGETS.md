# ميزانيات القبول قبل القياس

الإصدار 1 — 2026-11-06. جميع الأرقام التالية **أهداف تصميم غير مقاسة**، وليست سعة مضمونة أو نتائج. تغييرها بعد الفشل يحتاج قرارًا معلنًا مع حفظ النتيجة القديمة. تثبت نسخة هذا الملف وdataset/model/config/hardware مع run في 14–15.

| البعد | الحمل/الهدف المقترح | طريقة القياس والبوابة |
|---|---|---|
| مرجع العزل | مستأجران وثلاثة متاجر، كل دور، مصدر محذوف وسياسة متعارضة ومتغير SKU | منع كل حالات التسرب الحرجة؛ أي تسرب يمنع الإصدار |
| corpus بحث | نسخة 2,980 منتج إن أكد loader العدد والترخيص؛ synthetic منفصلة إذا تعذر | manifest بـrevision/hash/schema/license/count؛ ليست synthetic بديلًا عن إعادة الإنتاج |
| corpus تشغيل | 10,000 منتج و50,000 مقطع موزعة على 3 متاجر؛ stress منفصل 100,000 مقطع | قياس cold/warm وحذف أثناء query؛ أحجام مصطنعة معلنة |
| workload API | 20 مستخدمًا نشطًا، 10 طلبات/s مدة 15 دقيقة بعد warmup دقيقتين؛ 70% قراءة/20% بحث/10% كتابة | k6؛ 5xx أقل من 1% دون احتساب refusals الصحيحة أخطاء |
| workload إجابة | 2 سؤال/s، سقف 10 توليدات متزامنة؛ زيادة تدريجية لا ادعاء آلاف | تسجيل queue/provider/processing/delivery منفصلة؛ 429 معلنة |
| منصة مرجعية مقترحة | app/API: 4 vCPU و8GiB؛ worker: 4 vCPU و16GiB؛ Redis 1GiB؛ DB: 4 vCPU و8GiB | لم تحجز؛ سجل CPU/OS/region/disk/DB plan فعليًا قبل القياس |
| reranker/Llama | GPU منفصلة مقترحة 24GiB VRAM و32GiB RAM؛ quantization بعد تحقق | قياس peak RAM/VRAM وOOM؛ صلاحية الجهاز غير متحققة |
| واجهات | LCP ≤2.5s، INP ≤200ms، CLS ≤0.1؛ API CRUD p95 ≤500ms دون الشبكة الخارجية | Playwright/axe وLighthouse مختبر جوال وRUM لاحقًا؛ لا خلط synthetic وRUM |
| retrieval | p95 ≤1.5s بما فيه rerank ودون توليد | traces تحت corpus والحمل أعلاه؛ warm/cold منفصلان |
| إجابة | p95 ≤15s دون intentional_delay؛ acknowledgment ≤1s | قياس end-to-end مع الشبكة ومزود حقيقي؛ timeout إجمالي 30s ثم رد آمن |
| ingestion | ملف ≤20MiB، ≤200 صفحة، 100 ألف صف import/job، decompression ratio ≤100 وحد مطلق 200MiB | اختبارات رفض وحجر وحد وقت 10 دقائق/job؛ تجزئة الاستيراد بصفحات |
| retrieval/config | BM25 k1=1.2 b=0.75؛ RRF k=60؛ 30 لكل مسار/30 rerank/5–8 سياق | dev-only tuning؛ 6,000 input و800 output tokens كسقف بداية |
| تكلفة | dev evaluation ≤10 USD/run؛ staging ≤20 USD/day؛ تنبيه 80% وإيقاف أعمال اختيارية 100% | حساب tokens مع أسعار موثقة وقت التشغيل؛ لا سعر ثابت مخترع ولا إرسال بلا ميزانية مهيأة |
| جودة | Recall@10 ≥0.85، MRR@10 ≥0.70، faithfulness بشرية ≥0.95، ادعاءات غير مدعومة ≤0.02، امتناع صحيح ≥0.90 | 300 سؤال مقترح: 100 dev و200 test مجمد؛ نصف عربي، مراجعتان وحسم اختلاف؛ CI deterministic منفصل |
| مقارنة | Precision@5 وnDCG@10 وصحة الإجابة وفواصل ثقة وتغير النبرة | لا اشتراط تحسن غير مقاس؛ تقرير كل ablations بنفس Llama/config/data؛ لا تسرب gold في corpus |
| تعافٍ | RPO ≤24h وRTO ≤4h | استرجاع DB+files مع checksums وoutbound off وسجل محو حديث؛ تمرين فعلي في 13/17 |
| أمن ووصول | صفر تسرب حرج، صفر high/critical قابلة للاستغلال غير معالجة؛ صفر serious/critical axe | فحص يدوي أيضًا؛ ASVS L2 هدف مراجعة لا اعتماد |

سياسة freshness المقترحة: إعادة جلب السعر/المخزون عند كل جواب يؤكدهما؛ timeout 3s للأداة ثم امتناع عن التأكيد. الفهرس لا يثبت التوفر. السياسات بإصدار منشور فعال التاريخ؛ التعارض يطلب توضيحًا. معدل ومهل المزود الفعلية تضبط per-provider وفق الوثائق؛ لا تجاوز حدوده لتحقيق ميزانية محلية.
