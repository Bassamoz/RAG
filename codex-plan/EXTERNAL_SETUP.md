# المتطلبات الخارجية ومسارات التحقق

هذه قائمة إعداد، لا طلب لتزويد المحادثة بالأسرار. توضع القيم الحقيقية في secret manager أو ملفات بيئة محلية مستثناة من Git. يحتوي `.env.example` أسماء فقط وتعليقات دون قيم سرية.

| الخدمة | المطلوب من صاحب المشروع | ما يجب أن يفعله Codex | دليل التفعيل |
|---|---|---|---|
| Supabase | مشروع dev/staging/prod أو مشروع أولي مع فصل البيانات | إعداد Auth/DB/Storage، migrations، RLS، اتصال محدود الصلاحية | اختبارات قاعدة حقيقية وهوية متحققة وعزل متجرين |
| البريد | نطاق إرسال ومزوّد SMTP وحساب اختبار مملوك | قالب OTP عربي/إنجليزي، إعدادات الإرسال ومراقبة الفشل، توثيق SPF/DKIM/DMARC حسب المزوّد | وصول رمز حقيقي إلى صندوق الاختبار وتسجيل دخول به دون تسريب |
| MFA | تطبيق Authenticator للمستخدم الإداري | TOTP enrollment/challenge/recovery policy | إثبات منع العملية الحساسة قبل AAL2 ونجاحها بعده |
| تحقق رقم الاتصال | مزود SMS مدعوم وميزانية وأرقام اختبار | flow تحقق مستقل؛ يدعم Twilio إذا اختير/هيئ عبر المزوّد | الرقم لا يصبح verified قبل تحقق فعلي؛ لا يعد ربط WhatsApp Business |
| AI API | حساب يدعم المنطقة ووسيلة الدفع ومفتاح محدود الاستخدام | اختبار إتاحة النموذج الحالي وtimeouts/limits ومراقبة التكلفة | real-model smoke مع مصادر وإجابة وعزل؛ لا mock |
| Cross-Encoder | موارد كافية لتنزيل وتشغيل النموذج المرخص | revision ثابت وفحص حمل الذاكرة والسرعة واللغة | run حقيقي لأزواج عربية/إنجليزية، لا scores ثابتة |
| Llama البحثي | إتاحة/ترخيص النموذج وموارد محلية أو endpoint موثق | adapter evaluation فقط، تثبيت variant/revision/quantization | مقارنة مع/دون RAG بالنموذج نفسه؛ blocked إذا تعذر |

| Zid | حساب شريك وتطبيق ومتجر تجريبي وصلاحيات | موصل مستقل بنفس عقود المجال | دورة ربط ومزامنة وإلغاء ربط حقيقية |
| متجر خاص | تفويض النطاق ووثيقة API أو ملف منتجات | لا موصل سحري لكل موقع؛ mapping واضح وصلاحيات | استيراد مصرح مع مقارنة عدد/حقول وأخطاء الصفوف |
| WhatsApp | Meta app وWABA ورقم أعمال وصلاحيات/موافقات حسب نمط التكامل | Cloud API وonboarding وwebhook؛ وضع اختبار رسمي | رسالة واردة من رقم اختبار موافق ورد صحيح وحالات تسليم وتحويل |
| النشر | حساب استضافة ونطاق وDNS وبيئة أسرار | حاويات/TLS وhealth/migration وrollback | smoke على staging ثم production عند نشر مصرح |
| النسخ | وجهة نسخ خاصة ومفاتيح منفصلة | backup مع DB/files/manifests واسترجاع معزول | تقرير restore فعلي ومراجعة عدم إعادة بيانات محذوفة |
| الخط | ملفات ثمانية بترخيص استعمال مناسب للويب | self-host font وأوزانه مع fallback تطوير واضح | screenshots واختبار تحميل الخط؛ اعتماد بصري معلق إن غاب |

## قواعد التعامل مع العوائق

- لا تعطل تطوير ما يمكن تنفيذه محليًا بسبب نقص مفتاح. استخدم sandbox/mock واضحًا لحد الشبكة فقط، مع حالة حقيقية للميزة غير المتصلة.
- لا تضع بيانات حسابات المستخدم أو صلاحياته في Git ولا تطلب لصق secrets في تقرير Markdown.
- لا تُفعّل حملة أو تدعو أشخاصًا حقيقيين تلقائيًا لاختبار المنتج. استخدم صناديق وأرقام اختبار مملوكة ومصرحًا لها.
- وصول OAuth أو بريد في بيئة محلية لا يثبت جودة إعداد النطاق والإرسال في الإنتاج؛ لكل بيئة دليلها.
- لا يصنّف النظام `production_ready` بكامل نطاقه إذا كانت تكاملات معلنة مثل WhatsApp أو Salla/Zid غير متحققة. يمكن وصفه بصدق `code_complete` أو `local_verified` مع العوائق المتبقية.
- لا يشترط شراء جميع خدمات السحابة قبل كتابة الشفرة؛ اختبر صلاحية الوصول للخدمات المطلوبة مبكرًا لمنع إهدار الوقت على مسار غير متاح.
