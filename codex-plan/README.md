# حزمة برومبتات Codex لبناء منصة RAG لخدمة المتاجر

هذه حزمة تنفيذ متسلسلة من 19 مرحلة (00–18)، مبنية على البحث المرفق ذي 106 صفحات وعلى متطلبات بسام الحالية. تحتوي المواصفات، وخريطة البحث، ومتطلبات الاختبار، والبرومبتات، ونسخة البحث باسم بسيط. لا تحتوي برنامج المنصة جاهزًا؛ هي تعليمات بناء واختبار وتسليم يجب على Codex تنفيذها وإثبات نتائجها.

## طريقة الاستخدام

1. فك الحزمة وضع مجلد `codex-plan` داخل جذر مستودع المشروع الذي سيفتحه Codex. عند وجود مشروع سابق، أبقِه كما هو؛ المرحلة 00 تدققه وتكمله.
2. أرفق/اترك `codex-plan/references/research.pdf` متاحًا. لا ترسل كل المراحل في رسالة واحدة.
3. أرسل برومبت البداية أدناه. بعد انتهاء المرحلة 00 ودليلها، أرسل طلب تنفيذ المرحلة 01، ثم 02 بالتسلسل.
4. كل مرحلة تقرأ المواصفات والقرارات والحالة الحالية. إن قُطعت الجلسة، استخدم `RESUME_PROMPT.md`.
5. راجع تقرير كل مرحلة وأي `blocked_external`؛ تحتاج الخدمات الحقيقية حسابات ومفاتيح وتهيئة. لا تضع الأسرار في محادثة أو git.
6. عند نهاية المراحل، اقرأ `docs/RELEASE_READINESS.md` و`docs/IMPLEMENTATION_EXPLAINED_AR.md` اللذين سيولدهما Codex في المشروع.

برومبت البداية الجاهز:

```text
اقرأ codex-plan/README.md ثم codex-plan/MASTER_SPEC.md وcodex-plan/RESEARCH_MAP.md وcodex-plan/REQUIREMENTS.md. افحص المشروع الحالي وتعليماته. نفذ المرحلة codex-plan/prompts/00_research_and_plan.md فقط بكامل مخرجاتها، ثم سجل الحالة والتقرير والخطوة التالية. لا تبدأ من الصفر إن وجد مشروع، ولا تختلق نتائج اختبارات أو موافقات خدمات خارجية.
```

صيغة الانتقال لأي مرحلة:

```text
أكمل المشروع الحالي بتنفيذ ملف المرحلة التالي: codex-plan/prompts/01_foundation.md. اقرأ الحالة والقرارات السابقة أولًا، ثم نفذ المطلوب واختباراته وحدّث شرح التنفيذ العربي والتقرير. أصلح ما يلزم في الموجود دون إعادة بناء المشروع أو تغيير نطاقه بصمت.
```

غيّر اسم الملف وفق الجدول؛ لا تستخدم 01 لكل مرحلة. إذا ظهر اعتماد محجوب، يمكن تجهيز عمل مستقل لكن لا تمرر acceptance gate كأنه نجح.

## قرارات رئيسية

- ويب أولًا: Next.js + TypeScript، وخلفية Python/FastAPI مقسمة إلى وحدات. PostgreSQL/pgvector وRedis وSupabase Auth/Storage.
- البحث الأساسي: BM25 حقيقي + cosine + Cross-Encoder. FAISS موجود لتجارب البحث، وRRF موثق كإضافة هندسية.
- البريد برمز تحقق فعلي، وMFA مستقل. واتساب رسمي يحتاج حساب أعمال وتفويضًا؛ إدخال رقم لا يعني الاتصال.
- ألوان الواجهة: فاتح 60%، فحمي 30%، نعناعي 10%، ولون خطأ رابع عند الحاجة. الخط ثمانية عند توفير ملفاته المرخصة.
- لا GPS أو مزارعين أو دفع بالتقسيط، ولا Microservices/Kubernetes دون حاجة مقاسة.

## جودة التسليم

ينتج Codex أكواد الاختبارات وتشغيلها وتقاريرها؛ لا تكتفِ بعبارة «تم الاختبار». تحتاج النتائج environment/command/exit code/artifact/commit. الاختبار المتروك بسبب مفتاح أو حساب ناقص يبقى محجوبًا.

لا يمكن لأي نص برومبت أن يمنح ضمان 100% أو اعتمادًا أمنيًا. هذه الحزمة تضبط المتطلبات وطريقة إثباتها، ويُحسم النشر بالكود والاختبارات والربط الفعلي والموارد. راجع نطاق التكاملات مع مشرف المشروع لأن البحث يصف أيضًا بيئة محاكاة أضيق.
