# المرحلة 06: مصادر المعرفة والاستخراج والتقسيم والإصدارات

أنت مسؤول تنفيذ هذه المرحلة داخل المشروع الحالي. اقرأ تعليمات المستودع، و`codex-plan/MASTER_SPEC.md` و`codex-plan/RESEARCH_MAP.md` و`codex-plan/REQUIREMENTS.md`، ثم `docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` وقرارات ADR إن وجدت. افحص الموجود وأكمله؛ لا تبدأ تطبيقًا آخر ولا تعِد scaffold ولا تستبدل migrations قائمة.

نفذ الواجهة والخلفية والتخزين والصلاحيات واختبارات السلوك المطلوبة لهذه المرحلة فعليًا. ارجع إلى الوثائق الرسمية للمكتبات والمزودين قبل استخدام API. خذ القيم الافتراضية والحدود من MASTER_SPEC؛ أي تغيير قرار له ADR وتحديث العقود، لا تغيير صامت.

**الاعتماد:** تستكمل المراحل 00 إلى 05. تحقق من الأجزاء السابقة التي تعتمد عليها؛ يمكن تجهيز عمل مستقل عن خدمة محجوبة مع إبقاء اختبار الربط محجوبًا.

**المتطلبات:** R14، R16، R17، R18، R47.

## العمل المطلوب

1. واجهة مصادر المعرفة بتبويبات النص/FAQ/نموذج المتجر/ملف/صفحة. نموذج المتجر يغطي الشحن والرسوم والمدد والإرجاع والاستبدال والاستثناءات والضمان ووسائل الدفع وساعات الدعم. الحقول غير المعروفة تبقى ناقصة، ولا يملؤها النموذج بتخمين.
2. upload -> validate/quarantine -> extract -> normalize -> chunk -> embed -> index-ready -> review -> publish. status/progress/errors/cancel وإعادة محاولة idempotent. إضافة الذكاء لمسودة أو كشف نقص تتطلب اعتماد التاجر.
3. PDF نصي وDOCX ونص وMarkdown، واستفادة من importer المرحلة04. حافظ على عنوان ومقطع وصفحة/قسم. اكتشف PDF المصور وأظهر OCR required؛ إذا أضفت OCR فاختبر العربية وحدود الدقة والموارد واكتب مراجع المصدر.
4. crawler مصرح له بنطاق محدد، sitemap/selected pages وdepth/page/bytes/time limits وdedup. URL validation وDNS+redirect checks وegress protection ضد SSRF؛ لا تتجاوز authentication أو CAPTCHA. المتجر الديناميكي قد يُظهر partial import موثقًا.
5. طبق Semantic Chunking كما بالمواصفات: العناوين/الجمل والحدود الدلالية، مع حماية شروط الضمان والاستثناءات والأرقام، وfallback موصوف لا يغيّر الاسم لشيء لم ينفذ. احفظ النسخة الأصلية وnormalized search text منفصلين.
6. حفظ embedding model/revision/dimensions والـcontent hash، إعادة تضمين المتغير فقط، وإعادة بناء كاملة عند تغيير النموذج. جهز transactional publish pointer ونسخ immutable وmanifest، ولا تنشر نصف فهرس. استدعاء مكتبات الفهرسة يتم في المرحلة07.
7. اعمل source priority/effective date/visibility وpreview diff بين الإصدارات. كل source له public_for_assistant أو internal_only، ولا يدخل internal_only في chatbot corpus.

## الاختبارات المطلوبة

ملف سليم/فارغ/مشفر/مصور/معطوب/ضخم وDOCX zip bomb اصطناعي، MIME spoof، path traversal، URL إلى localhost/private/IPv6/link-local وredirect إلى شبكة داخلية وDNS rebinding عبر test network محلية.

اختبارات جمل عربية ونفي وأكواد ومواصفات وجداول وسياسة لا تنفصل استثناءاتها، dedup لا يدمج متجرين، embedding timeout/dimension mismatch، worker crash، حذف المصدر أثناء الفهرسة، وتعديل نسختين بالتزامن.

## القبول

يستطيع التاجر رؤية ما استُخرج واعتماده أو رفضه. تعديل مصدر لا يفسد النسخة المنشورة، والحذف يمنع استعماله فورًا حتى اكتمال التنظيف. لا أسرار أو PII في logs أو indexed examples.

## طريقة التحقق والتسليم في هذه المرحلة

- اكتب أكواد الاختبارات في المستودع، وشغّل الفحوص المتأثرة فعلًا. تحقق من النتائج وأصلح الفشل ثم أعد الفحوص اللازمة فقط. لا اختبارات تؤكد mock فحسب ولا تعطيل assertions أو security rules لتمرير النتائج.
- سجّل الأمر الفعلي والنتيجة وexit code والبيئة ونسخة الكود ومسار artifact. افصل اختبارات الوحدات والعقود عن اختبار المزود/النموذج الحي. نقص المفاتيح يسجل `blocked_external`، ولا يعادل نجاحًا.
- حدث `docs/REQUIREMENTS_TRACEABILITY.md` و`docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` و`docs/IMPLEMENTATION_EXPLAINED_AR.md` وتقرير المرحلة في `docs/phase-reports/`. لا تخزن أسرارًا أو بيانات شخصية في الأدلة.
- تقرير Markdown بالعربية يوضح: المشكلة التي حلت، الملفات والوحدات، كيف تتدفق البيانات، القرارات، تعليقات الكود المهمة، أوامر التشغيل والاختبارات، ما نجح وما فشل وما لم يُختبر ولماذا، والجزء التالي بدقة.
- راجع diff واحذف الكود الميت والتكرار والمكتبات التي لم تعد لازمة لهذه المرحلة دون الإضرار بعمل المستخدم. اترك المشروع قابلًا للاستمرار.
- لا تنتقل تلقائيًا إلى مرحلة أخرى. إذا انقطع السياق، احفظ checkpoint للعمل المكتمل وأول خطوة باقية. لا تدّع اكتمال مرحلة أو جاهزية نشر قبل أدلة قبولها.
