# المرحلة 13: دورة الحياة والحذف والاسترجاع والنسخ الاحتياطي

أنت مسؤول تنفيذ هذه المرحلة داخل المشروع الحالي. اقرأ تعليمات المستودع، و`codex-plan/MASTER_SPEC.md` و`codex-plan/RESEARCH_MAP.md` و`codex-plan/REQUIREMENTS.md`، ثم `docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` وقرارات ADR إن وجدت. افحص الموجود وأكمله؛ لا تبدأ تطبيقًا آخر ولا تعِد scaffold ولا تستبدل migrations قائمة.

نفذ الواجهة والخلفية والتخزين والصلاحيات واختبارات السلوك المطلوبة لهذه المرحلة فعليًا. ارجع إلى الوثائق الرسمية للمكتبات والمزودين قبل استخدام API. خذ القيم الافتراضية والحدود من MASTER_SPEC؛ أي تغيير قرار له ADR وتحديث العقود، لا تغيير صامت.

**الاعتماد:** تستكمل المراحل 00 إلى 12. تحقق من الأجزاء السابقة التي تعتمد عليها؛ يمكن تجهيز عمل مستقل عن خدمة محجوبة مع إبقاء اختبار الربط محجوبًا.

**المتطلبات:** R18، R37، R38، R39، R47.

## العمل المطلوب

1. استكمل edit/archive/soft-delete/trash/restore للعناصر المناسبة وصلاحياتها وretention. حدد ما هو يدوي وما هو خارجي، وما يعاد كمسودة قبل النشر. لا يحذف اختيار «إخفاء منتج» المنتج في سلة/زد.
2. حذف نهائي/إغلاق منشأة مع خطوة تأكيد واضحة وإعادة تحقق وصلاحية مالك، dry-run نطاق العملية، job قابل للتتبع، وحظر استخدام المصادر فورًا. لا تعرض خيار restore لمحو انتهى.
3. طبّق المحو في DB وstorage وembeddings وفهارس BM25/FAISS وcache والتصدير والمهام المعلقة. tombstone/deletion epoch تمنع job مؤجلًا من إعادة البيانات. audit يحتفظ بالحد الأدنى بلا المحتوى المحذوف.
4. privacy export للتاجر وفق نطاقه، وسياسات احتفاظ للرسائل/المرفقات/التقييمات/السجلات؛ masking وتقليل PII. هوية مشتركة لعضو في عدة منشآت لا تُمحى من الجميع عند مغادرته منشأة واحدة.
5. backup تشغيلي يشمل DB وobject files/manifests وإعدادات إعادة الفهرسة، تشفير ومفاتيح منفصلة وجدول retention ومراقبة نجاح/فشل. لا تفترض أن نسخة Supabase DB تحتوي bytes الملفات.
6. restore script إلى بيئة معزولة بصلاحيات تشغيلية فقط. أوقف outbound وwebhook processors، تحقق schema/row counts/checksums/relationships/authorization، وأعد الفهارس. لا تستبدل إنتاجًا تلقائيًا أثناء تجربة.
7. احتفظ بسجل محو أحدث مستقل عن نقطة النسخة واستعمله قبل إعادة الخدمة حتى لا تحيي بيانات ممحوة. سجل زمن الاسترجاع والفقد المقاس RTO/RPO بدل وعود. وثق الحدود عند عدم القدرة على محو نسخة immutable قبل انتهاء احتفاظها.

## الاختبارات المطلوبة

restore مصدر كان منشورًا، تعارض نسخة أحدث، محو محادثة أثناء توليد/إرسال، إعادة مزامنة منتج مخفي، حذف source أثناء embeddings، tenant آخر يحاول restore/export، membership حذف مع مستخدم متعدد المنشآت.

تمرين فعلي: seed بيانات وملفات -> backup -> تعديل وحذف/طلب محو -> restore إلى بيئة أخرى -> إعادة تطبيق سجل المحو -> فحص ملفات ومجاميع وصلاحيات -> إثبات أن رسائل قديمة لم تُرسل. اختبر نسخة ناقصة/فاسدة ومفتاح غير متاح دون تسريب.

## القبول

السلة والاسترجاع والمحو تعمل من الواجهة، وتمرين backup/restore له تقرير حقيقي. ملف backup دون تجربة استعادة لا يكفي. بيانات محذوفة لا تعود عبر cache أو job أو restore.

## طريقة التحقق والتسليم في هذه المرحلة

- اكتب أكواد الاختبارات في المستودع، وشغّل الفحوص المتأثرة فعلًا. تحقق من النتائج وأصلح الفشل ثم أعد الفحوص اللازمة فقط. لا اختبارات تؤكد mock فحسب ولا تعطيل assertions أو security rules لتمرير النتائج.
- سجّل الأمر الفعلي والنتيجة وexit code والبيئة ونسخة الكود ومسار artifact. افصل اختبارات الوحدات والعقود عن اختبار المزود/النموذج الحي. نقص المفاتيح يسجل `blocked_external`، ولا يعادل نجاحًا.
- حدث `docs/REQUIREMENTS_TRACEABILITY.md` و`docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` و`docs/IMPLEMENTATION_EXPLAINED_AR.md` وتقرير المرحلة في `docs/phase-reports/`. لا تخزن أسرارًا أو بيانات شخصية في الأدلة.
- تقرير Markdown بالعربية يوضح: المشكلة التي حلت، الملفات والوحدات، كيف تتدفق البيانات، القرارات، تعليقات الكود المهمة، أوامر التشغيل والاختبارات، ما نجح وما فشل وما لم يُختبر ولماذا، والجزء التالي بدقة.
- راجع diff واحذف الكود الميت والتكرار والمكتبات التي لم تعد لازمة لهذه المرحلة دون الإضرار بعمل المستخدم. اترك المشروع قابلًا للاستمرار.
- لا تنتقل تلقائيًا إلى مرحلة أخرى. إذا انقطع السياق، احفظ checkpoint للعمل المكتمل وأول خطوة باقية. لا تدّع اكتمال مرحلة أو جاهزية نشر قبل أدلة قبولها.
