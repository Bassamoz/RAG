# المرحلة 12: التحليلات والتقارير والتقييم والاستهلاك

أنت مسؤول تنفيذ هذه المرحلة داخل المشروع الحالي. اقرأ تعليمات المستودع، و`codex-plan/MASTER_SPEC.md` و`codex-plan/RESEARCH_MAP.md` و`codex-plan/REQUIREMENTS.md`، ثم `docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` وقرارات ADR إن وجدت. افحص الموجود وأكمله؛ لا تبدأ تطبيقًا آخر ولا تعِد scaffold ولا تستبدل migrations قائمة.

نفذ الواجهة والخلفية والتخزين والصلاحيات واختبارات السلوك المطلوبة لهذه المرحلة فعليًا. ارجع إلى الوثائق الرسمية للمكتبات والمزودين قبل استخدام API. خذ القيم الافتراضية والحدود من MASTER_SPEC؛ أي تغيير قرار له ADR وتحديث العقود، لا تغيير صامت.

**الاعتماد:** تستكمل المراحل 00 إلى 11. تحقق من الأجزاء السابقة التي تعتمد عليها؛ يمكن تجهيز عمل مستقل عن خدمة محجوبة مع إبقاء اختبار الربط محجوبًا.

**المتطلبات:** R35، R36، R47.

## العمل المطلوب

1. عرّف metric dictionary قبل الرسوم: conversations، bot-resolved وفق إغلاق/تقييم معلن، handoff rate، unanswered، first response وsubsequent latency، CSAT مع عدد التقييمات ومقياسه، أخطاء المزامنة، tokens/cost إن توفرت أسعار موثقة.
2. استمد الأرقام من events حقيقية مع event time وUTC/tenant timezone وdenominators صحيحة. فك duplicate events ولا تحسب acknowledgment حلًا ولا رد الموظف إنجازًا للبوت. افصل processing وqueue وintentional delay.
3. واجهات overview وتحليلات بمحدد الفترة والمتجر والقناة، وأهم الفجوات المعرفية، وتقارير محادثات/مزامنة/استهلاك/تقييم. حالة no data واضحة؛ لا استنتاج زيادة مبيعات أو خفض تذاكر بلا baseline.
4. CSV/XLSX للبيانات الجدولية، PDF وMarkdown للتقرير المقروء، jobs كبيرة مع progress/download expiry. private storage وصلاحية تحميل حية حتى بعد توليد التقرير. sanitize formula cells ولا تصدر PII افتراضيًا.
5. PDF عربي بخط مرخص يدعم التشكيل/RTL؛ اختبر rendering ومطابقة المجاميع. لا تستخدم صور جدول غير قابل للقراءة إذا أمكن نص صحيح.
6. usage ledger وإعداد quota للتاجر، ميزانية tokens وعدد الطلبات ومكافحة abuse؛ اجعل تكلفة نموذج/عملة/سعر بتاريخ واضح، والقيمة unknown إن تعذر المصدر. لا تضف مدفوعات أو فواتير متجر غير مطلوبة.

## الاختبارات المطلوبة

حسابات على dataset صغير معلوم النتائج: حدود التاريخ/timezone، تقييم واحد/لا تقييم، حذف محادثة مع مراعاة سياسة aggregate، duplicate/out-of-order events، pagination وlarge export، currency rounding.

تنزيل تقرير بمعرف tenant آخر أو رابط منتهي أو مستخدم سُحبت صلاحيته، CSV formula injection، PDF RTL وحروف وأرقام، job cancel/retry، quota race بين طلبات متزامنة، وعدم إظهار تكلفة تقديرية كقيمة محسوبة فعلًا.

## القبول

الأرقام متطابقة مع مصدرها وموثقة التعريف. تقرير قابل للتنزيل فعليًا مع حدود الخصوصية، والرسوم تعرض بيانات حقيقية أو حالة فارغة. CSAT ونتائج البحث شيئان منفصلان.

## طريقة التحقق والتسليم في هذه المرحلة

- اكتب أكواد الاختبارات في المستودع، وشغّل الفحوص المتأثرة فعلًا. تحقق من النتائج وأصلح الفشل ثم أعد الفحوص اللازمة فقط. لا اختبارات تؤكد mock فحسب ولا تعطيل assertions أو security rules لتمرير النتائج.
- سجّل الأمر الفعلي والنتيجة وexit code والبيئة ونسخة الكود ومسار artifact. افصل اختبارات الوحدات والعقود عن اختبار المزود/النموذج الحي. نقص المفاتيح يسجل `blocked_external`، ولا يعادل نجاحًا.
