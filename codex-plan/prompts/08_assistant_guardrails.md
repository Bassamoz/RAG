# المرحلة 08: تنسيق RAG والأدوات والإجابة المسندة

أنت مسؤول تنفيذ هذه المرحلة داخل المشروع الحالي. اقرأ تعليمات المستودع، و`codex-plan/MASTER_SPEC.md` و`codex-plan/RESEARCH_MAP.md` و`codex-plan/REQUIREMENTS.md`، ثم `docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` وقرارات ADR إن وجدت. افحص الموجود وأكمله؛ لا تبدأ تطبيقًا آخر ولا تعِد scaffold ولا تستبدل migrations قائمة.

نفذ الواجهة والخلفية والتخزين والصلاحيات واختبارات السلوك المطلوبة لهذه المرحلة فعليًا. ارجع إلى الوثائق الرسمية للمكتبات والمزودين قبل استخدام API. خذ القيم الافتراضية والحدود من MASTER_SPEC؛ أي تغيير قرار له ADR وتحديث العقود، لا تغيير صامت.

**الاعتماد:** تستكمل المراحل 00 إلى 07. تحقق من الأجزاء السابقة التي تعتمد عليها؛ يمكن تجهيز عمل مستقل عن خدمة محجوبة مع إبقاء اختبار الربط محجوبًا.

**المتطلبات:** R23، R24، R25، R26، R29، R47.

## العمل المطلوب

1. منسق حوار واحد للقنوات: تحقق input والهوية/المتجر -> نية وكيانات -> سؤال توضيحي عند الحاجة -> retrieval/أدوات -> سياق bounded -> generation -> validation -> outcome. دعم الأنواع الثمانية في البحث والمتابعة متعددة الأدوار.
2. provider adapter للنموذج مع timeouts/retries/circuit breaker/token budget. عند اختيار OpenAI راجع Responses API الحالي؛ لا تفترض أن كل نموذج يدعم المعلمات نفسها. لا ترسل corpus كاملًا أو secrets أو معلومات خاصة غير لازمة.
3. prompt templates ذات إصدارات تفصل التعليمات عن المحتوى. إجابة structured بمصادر قابلة للتحقق؛ sanitize العرض وروابط allowlist. تحقق من citations/IDs وحقول الأسعار والمتغيرات والعملة والتواريخ.
4. الأدوات read-only وجداول schemas صارمة؛ الخادم يتحقق من كل argument ومن customer authorization في بيانات الطلب. طبّق freshness policy على السعر/المخزون والعرض؛ cache قديم لا يصبح حقيقة. عرّف كيفية التصرف عند تعطل المصدر.
5. منع RAG poisoning وحقن التعليمات عبر النصوص/metadata/الأسلوب، ومنع طلب كشف prompts/secrets أو بيانات متجر آخر. استخدم ضوابط حتمية للأدوار والحقول مع تحقق جواب متناسب؛ لا تتكل على prompt وحده.
6. إعداد نبرة يدوية وحجم جواب؛ مسار استخراج خصائص أسلوب من نص منزوع الهوية ويعتمد قبل النشر. لا أسلوب يقلد شخصًا بالاسم ولا محادثات خام تلقائية لدى المزود. المصادر تتحكم بالحقائق والنبرة لا تغير السياسة.
7. إرجاع answered/needs_clarification/insufficient_evidence/out_of_scope/tool_unavailable/handoff_required. حافظ على trace مختصر للأدلة والنتيجة والمدة، دون hidden reasoning أو بيانات خاصة غير لازمة. اربط playground بالمسار نفسه.

## الاختبارات المطلوبة

أسئلة مواصفات وشحن وضمان وإرجاع وتوصية وFAQ، نفي عربي، ضمير مبهم، follow-up لمتغير مختلف، حد سعر، تعارض سياستين، لا معرفة، مصدر محذوف بعد retrieval، live price مختلف عن تاريخ المحادثة.

prompt injection في ملف وسؤال وأسلوب، hallucinated citation، invalid tool args، URL خارج النطاق، طلب لعميل آخر، provider timeout/429 وماليات غير مدعومة. اختبار لا يفصح أن رمز طلب موجود أصلًا لعميل غير مخول.

## القبول

المساعد يجيب بدليل أو يطلب توضيحًا/يمتنع؛ لا يختلق سعرًا أو سياسة. tests محلية حتمية ثم smoke بنموذج حقيقي منفصل، والتقرير يوضح ما قيس فعلًا. التحكم في الصلاحيات مستقل عن حكم النموذج.

## طريقة التحقق والتسليم في هذه المرحلة

- اكتب أكواد الاختبارات في المستودع، وشغّل الفحوص المتأثرة فعلًا. تحقق من النتائج وأصلح الفشل ثم أعد الفحوص اللازمة فقط. لا اختبارات تؤكد mock فحسب ولا تعطيل assertions أو security rules لتمرير النتائج.
- سجّل الأمر الفعلي والنتيجة وexit code والبيئة ونسخة الكود ومسار artifact. افصل اختبارات الوحدات والعقود عن اختبار المزود/النموذج الحي. نقص المفاتيح يسجل `blocked_external`، ولا يعادل نجاحًا.
- حدث `docs/REQUIREMENTS_TRACEABILITY.md` و`docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` و`docs/IMPLEMENTATION_EXPLAINED_AR.md` وتقرير المرحلة في `docs/phase-reports/`. لا تخزن أسرارًا أو بيانات شخصية في الأدلة.
- تقرير Markdown بالعربية يوضح: المشكلة التي حلت، الملفات والوحدات، كيف تتدفق البيانات، القرارات، تعليقات الكود المهمة، أوامر التشغيل والاختبارات، ما نجح وما فشل وما لم يُختبر ولماذا، والجزء التالي بدقة.
- راجع diff واحذف الكود الميت والتكرار والمكتبات التي لم تعد لازمة لهذه المرحلة دون الإضرار بعمل المستخدم. اترك المشروع قابلًا للاستمرار.
- لا تنتقل تلقائيًا إلى مرحلة أخرى. إذا انقطع السياق، احفظ checkpoint للعمل المكتمل وأول خطوة باقية. لا تدّع اكتمال مرحلة أو جاهزية نشر قبل أدلة قبولها.
