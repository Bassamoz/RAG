# المرحلة 04: الكتالوج والمتغيرات والسياسات والاستيراد

أنت مسؤول تنفيذ هذه المرحلة داخل المشروع الحالي. اقرأ تعليمات المستودع، و`codex-plan/MASTER_SPEC.md` و`codex-plan/RESEARCH_MAP.md` و`codex-plan/REQUIREMENTS.md`، ثم `docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` وقرارات ADR إن وجدت. افحص الموجود وأكمله؛ لا تبدأ تطبيقًا آخر ولا تعِد scaffold ولا تستبدل migrations قائمة.

نفذ الواجهة والخلفية والتخزين والصلاحيات واختبارات السلوك المطلوبة لهذه المرحلة فعليًا. ارجع إلى الوثائق الرسمية للمكتبات والمزودين قبل استخدام API. خذ القيم الافتراضية والحدود من MASTER_SPEC؛ أي تغيير قرار له ADR وتحديث العقود، لا تغيير صامت.

**الاعتماد:** تستكمل المراحل 00 إلى 03. تحقق من الأجزاء السابقة التي تعتمد عليها؛ يمكن تجهيز عمل مستقل عن خدمة محجوبة مع إبقاء اختبار الربط محجوبًا.

**المتطلبات:** R10، R11، R40، R47.

## العمل المطلوب

1. ابنِ CRUD حقيقيًا للمنتجات اليدوية والتصنيفات والمتغيرات والسياسات وFAQs؛ forms وvalidation وsearch/filter/pagination وصلاحيات tenant/store. اجعل الوراثة من سياسة المتجر ثم الاستثناء المعتمد للمنتج واضحة.
2. دعم SKU فريد ضمن متجر، صور وروابط مسموحة، Decimal وcurrency، السعر الأصلي/المخفض وتواريخه إن وجدت، متغيرات اللون/المقاس والتوفر. unknown stock ليس صفرًا، وunlimited ليس رقمًا مخترعًا.
3. المنتجات الخارجية read-only من المصدر مع إعداد ظهور محلي؛ لا label «تم تحديث سلة» عند تغيير محلي. سجل مصدر كل حقل وآخر تحديث، ولا تعرض cost_price أو أسرار العروض في واجهات العميل.
4. CSV/XLSX importer: تحميل آمن، اختيار الأعمدة، معاينة، تحقق كل صف، أخطاء قابلة للتنزيل، duplicate policy وidempotency وjob progress/cancel. لا تنفذ formulas/macros؛ تعامل مع قيمها وفق سياسة واضحة.
5. جهز dataset importer لحقول Amazon المذكورة في البحث مع provenance، وفصل Q&A المرشحة للتقييم عن النص المفهرس. لا تنزل/توزع بيانات غامضة الترخيص تلقائيًا؛ fixtures الاصطناعية موجودة للتطوير ومستقلة.
6. سجل audit للتعديل وتعارض version؛ جهز soft-delete contract الذي تكمله مرحلة13، ولا تحذف بيانات المصدر الخارجي.

## الاختبارات المطلوبة

قيم نقدية وكسور وعملات، متغيرات متشابهة، خصم منتهٍ، negative/invalid quantities، unique constraints مقيدة بالمتجر، mass assignment، تحديثان متزامنان، مصدر خارجي لا يقبل تعديلًا غير مدعوم.

ملف صحيح وآخر بأعمدة ناقصة/ترميز عربي/صفوف معطوبة/حجم زائد/صيغة خادعة/formula، استيراد مكرر، وإعادة محاولة job بعد توقفه. E2E إنشاء منتج ثم متغير وسياسة وFAQ وتحريرها ومعاينة أثرها.

## القبول

كتالوج وسياسات قابلة للاستخدام ببيانات حقيقية أو اصطناعية موسومة، دون claims مخزون حي. ناتج importer له counts صحيحة وأخطاء صفوف ودليل عدم تكرار، ويستطيع خط المعرفة قراءة المحتوى المنشور لاحقًا.

## طريقة التحقق والتسليم في هذه المرحلة

- اكتب أكواد الاختبارات في المستودع، وشغّل الفحوص المتأثرة فعلًا. تحقق من النتائج وأصلح الفشل ثم أعد الفحوص اللازمة فقط. لا اختبارات تؤكد mock فحسب ولا تعطيل assertions أو security rules لتمرير النتائج.
- سجّل الأمر الفعلي والنتيجة وexit code والبيئة ونسخة الكود ومسار artifact. افصل اختبارات الوحدات والعقود عن اختبار المزود/النموذج الحي. نقص المفاتيح يسجل `blocked_external`، ولا يعادل نجاحًا.
- حدث `docs/REQUIREMENTS_TRACEABILITY.md` و`docs/PROJECT_STATE.json` و`docs/NEXT_ACTIONS.md` و`docs/IMPLEMENTATION_EXPLAINED_AR.md` وتقرير المرحلة في `docs/phase-reports/`. لا تخزن أسرارًا أو بيانات شخصية في الأدلة.
- تقرير Markdown بالعربية يوضح: المشكلة التي حلت، الملفات والوحدات، كيف تتدفق البيانات، القرارات، تعليقات الكود المهمة، أوامر التشغيل والاختبارات، ما نجح وما فشل وما لم يُختبر ولماذا، والجزء التالي بدقة.
- راجع diff واحذف الكود الميت والتكرار والمكتبات التي لم تعد لازمة لهذه المرحلة دون الإضرار بعمل المستخدم. اترك المشروع قابلًا للاستمرار.
- لا تنتقل تلقائيًا إلى مرحلة أخرى. إذا انقطع السياق، احفظ checkpoint للعمل المكتمل وأول خطوة باقية. لا تدّع اكتمال مرحلة أو جاهزية نشر قبل أدلة قبولها.
